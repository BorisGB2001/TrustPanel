# TrustPanel

[English version](README.md)

Веб-панель для VPN-сервера [TrustTunnel](https://github.com/TrustTunnel/TrustTunnel) (служба systemd `trusttunnel`). Показывает, кто подключён, откуда и сколько трафика тратит; добавляет, отключает и удаляет клиентов и выдаёт их конфиги (ссылка `tt://` с QR-кодом для приложений TrustTunnel, `.toml` для CLI-клиента). Ещё в ней есть алерты, квоты трафика, группы и подгруппы клиентов (головная организация → филиалы → отделы) со своими администраторами, помесячный архив, личный кабинет клиента, уведомления в Telegram и на почту и зашифрованные бэкапы.

TrustPanel — перенос [AWG Panel](https://github.com/BorisGB2001/awg-panel) (такой же панели для AmneziaWG) на TrustTunnel.

| | |
|---|---|
| Адрес | `https://<ip-сервера>:15443` (порт — `PANEL_PORT` в `.env`; сертификат от внутреннего CA Caddy — **порт 80 не используется**) |
| Каталог | `/opt/trust-panel` на сервере TrustTunnel |
| Контейнеры | `trust-panel` (Python, FastAPI), `trust-panel-caddy` (HTTPS) |
| Данные | `/opt/trust-panel/data`: `panel.db` (SQLite), `backups/` (credentials.toml перед каждым изменением, БД), `geo/` (DB-IP), `data.key` |
| Вход | пользователь `admin`, пароль + код TOTP |

## Возможности

- **Обзор**: онлайн сейчас и пик, трафик за 24 ч / 7 / 30 дней, топ-10 по трафику за сегодня и за месяц (полосы скачано / отдано, график при наведении), трафик по группам, все клиенты: статус, когда был, откуда подключается (страна, город, провайдер), трафик за сегодня и всего.
- **Карточка клиента**: сессии, IP-адреса с гео, тепловая карта активности по часам, события, квота, группа, ссылка в кабинет и контакты.
- **Управление**: добавить клиента (логин из имени или вручную, случайный пароль), переименовать, отключить / включить (пароль остаётся у панели — тот же конфиг снова работает), удалить, выдать новый пароль.
- **Конфиги**: ссылка `tt://` с QR-кодом и `.toml` для CLI-клиента — их выгружает сам endpoint (`trusttunnel_endpoint -c`), поэтому они всегда совпадают с настройками сервера. Отправка клиенту в Telegram или на почту, одноразовая ссылка на бота.
- **События и алерты**: подключения, смена IP, конфиг с нескольких мест, новая страна, всплески трафика, пороги квот, ни разу не подключавшиеся и давно неактивные клиенты, перезапуск или недоступность endpoint'а, диск и таблица соединений, подбор пароля. Алерты — в Telegram администраторам (с тихими часами).
- **Группы и администраторы**: группы вкладываются друг в друга (головная организация → филиалы → отделы, любая глубина), на каждой странице — путь по группам; клиенты, трафик и квота группы считаются вместе с подгруппами. Супер-администратор видит всё; администратор группы — только клиентов своих групп и их подгрупп, подгруппы он может создавать, переносить и удалять. Квоты трафика на группу или клиента за день / месяц с алертом или автоматическим отключением.
- **Личный кабинет** (`/me`, персональная ссылка): свой трафик, сессии, квота, по разрешению — скачивание конфига, ежедневная сводка картинкой и уведомления в Telegram или на почту.
- **Бэкапы** в Telegram / на почту по расписанию, зашифрованные вашим паролем (AES-256-GCM, scrypt): весь портал (БД, `.env`, `data.key`, настройки TrustTunnel) или, у администратора группы, конфиги его групп. Восстановление на этом же сервере со страницы «Бэкапы» или на новом — `restore.sh`.
- **Доступ по IP** к админской части, интерфейс на русском и английском, светлая и тёмная тема.

## Как устроено

- Endpoint хранит пользователей в `credentials.toml` и читает его **только при старте** (SIGHUP перечитывает лишь TLS-хосты). Поэтому любое изменение состава клиентов — это блокировка → бэкап `credentials.toml` → запись → `systemctl restart trusttunnel` → проверка, что служба поднялась. При сбое файл возвращается и endpoint перезапускается ещё раз. **Перезапуск на секунду-две обрывает все туннели; приложения TrustTunnel переподключаются сами.** Переименование, квоты, группы и настройки кабинета ничего не перезапускают.
- Онлайн, IP клиента и трафик — из метрик endpoint'а (`/clients` при `per_client_metrics = true`) каждые `POLL_INTERVAL` секунд. Счётчики обнуляются при перезапуске endpoint'а — панель это учитывает.
- Пользователи, добавленные в `credentials.toml` вручную, импортируются сами (с паролем — чтобы панель могла выдать их конфиг) и попадают в «без группы».
- Контейнер панели работает с `network_mode: host`, `pid: host` и `privileged`: метрики слушают `127.0.0.1`, а `systemctl` запускается в namespace'ах хоста через `nsenter`. Каталог endpoint'а смонтирован в контейнер; статически собранный `trusttunnel_endpoint` запускается прямо в нём для выгрузки конфигов.
- Чего TrustTunnel не сообщает, панель показать не может: нет посещённых сайтов / журнала DNS и блокировки по сайтам, как в AWG Panel.

## Требования

- Linux-сервер с Docker (compose v2) и endpoint TrustTunnel, установленный службой systemd (`/opt/trusttunnel`, см. README TrustTunnel).
- В `vpn.toml` endpoint'а — метрики по клиентам, только на localhost:

  ```toml
  [metrics]
  address = "127.0.0.1:1987"
  request_timeout_secs = 3
  per_client_metrics = true
  ```

- В `hosts.toml` основной хост — **имя**, а не IP: endpoint обрывает TLS без SNI, а IP не может быть SNI. Без домена подойдёт wildcard-DNS вида `203-0-113-10.sslip.io` (указывает на 203.0.113.10) с самоподписанным сертификатом; сертификат вшивается в выгружаемые конфиги.
- Свободный TCP-порт для панели (`PANEL_PORT`, по умолчанию 15443), открытый в файрволе.

## Установка

```bash
# на рабочей машине, из корня репозитория
cp .env.example .env.server         # заполнить PANEL_HOST, PUBLIC_HOST, SESSION_SECRET, DATA_KEY (команды — в файле)
scp .env.server root@<server>:/opt/trust-panel/.env && ssh root@<server> chmod 600 /opt/trust-panel/.env
./deploy.sh root@<server>           # копирует код, собирает образ, гоняет тесты, запускает панель
ssh root@<server> 'cd /opt/trust-panel && ./init-admin.sh && docker compose up -d caddy && ufw allow 15443/tcp'
```

`init-admin.sh` спрашивает пароль администратора и показывает QR-код для приложения-аутентификатора. Дальше — `https://<ip-сервера>:15443`. Браузер один раз предупредит о сертификате: его выпустил локальный CA Caddy. Сверьте отпечаток (`openssl s_client -connect <ip>:15443 | openssl x509 -noout -fingerprint -sha256` на сервере) или добавьте в доверенные корень `docker compose exec caddy cat /data/caddy/pki/authorities/local/root.crt`.

## Обновление

```bash
./deploy.sh root@<server>
```

Тесты прогоняются внутри нового образа до замены контейнера; база мигрирует сама.

## Состояние и логи

```bash
curl -s http://127.0.0.1:8081/healthz           # на сервере: опрос, версия, схема
docker compose logs -f panel                     # в /opt/trust-panel
journalctl -u trusttunnel -f                     # endpoint
```

## Бэкапы и восстановление

- Перед каждым изменением клиентов: `data/backups/<время>-<операция>/credentials.toml` (хранятся последние 200). Ночью — копия базы в `data/backups/db/` (14 штук).
- Страница «Бэкапы»: зашифрованные бэкапы в Telegram / на почту по расписанию. Расшифровать вручную: `python3 -m app.backup decrypt <файл>.ttbak`.
- Восстановление на этом же сервере: «Бэкапы» → файл `.ttbak`, пароль и что восстановить (база, настройки TrustTunnel).
- Новый сервер: установить TrustTunnel и Docker, `./deploy.sh`, затем в `/opt/trust-panel` — `./restore.sh <файл>.ttbak [новый-ip]`.

## Доступ по IP

На странице «Администраторы» (супер-администратор) админскую часть, включая вход, можно открыть только с перечисленных адресов и подсетей; личный кабинет клиентов остаётся доступен. Если закрыли доступ себе: `./ip-allow.sh list | add <ip> | remove <n> | clear` на сервере.

## Особенности

- Любое изменение состава клиентов перезапускает endpoint (см. «Как устроено»).
- Браузер предупреждает о самоподписанном сертификате панели, пока вы не добавите в доверенные локальный CA Caddy.
- Время сессий — с точностью опроса (`POLL_INTERVAL` секунд), а не точные моменты подключения.

## Разработка

```bash
cd panel && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest httpx

```
